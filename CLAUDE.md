# MountTrail: notes for Claude sessions

Keep the structure described in ARCHITECTURE.md. Before adding code, find the
file that already owns that job (ARCHITECTURE.md's "Where to find X" table)
and put it there.

- Layers stay separate: `Data/` tables (generated by `tools/`), `Logic/` pure
  Lua with no WoW API, `Game/API.lua` the only WoW API wrapper, `Integrations/`
  other addons (always behind pcall), `UI/` frames.
- UI ownership: `UI/Frame.lua` the main window and refresh hooks,
  `UI/Widgets.lua` reusable widgets, `UI/Nav.lua` the navigation column,
  `UI/List.lua` the mount list, `UI/Search.lua` search glue, one file per view
  or window otherwise.
- Keep files under about 1,000 lines where practical. When a file grows past
  that, split it by job (as Frame.lua -> Widgets.lua / Nav.lua was), add the
  new file to `MountTrail.toc` next to its parent, and to `COMPANIONS` in
  `tests/harness.lua` if specs load the parent.
- No globals: everything on `ns` / `ns.UI`. Strings through `L[...]`
  (`Core/Locale.lua`). Widgets created once and reused, never in refresh paths.
- Remove dead code instead of parking it.
- Every change: tests in `tests/`, `python3 tools/run_tests.py` green, README /
  ARCHITECTURE.md updated when behaviour or structure changes.
- Tell the user when a change adds or removes a file: that needs a full game
  restart, not /reload.
- Develop on the branch the session names and push after each feature.
- Commit messages in plain words, no `feat:` / `fix:` / `chore:` style
  prefixes: say what changed for the player, e.g. "Drop alert: chime when a
  mount reaches your bags".
