# MountTrail architecture

This page is a map of the code for people changing it. For setup, tests and
code style see [CONTRIBUTING.md](CONTRIBUTING.md); for what the addon does
from a player's side see [README.md](README.md).

## Layers

The files load in the order `MountTrail.toc` lists them, and each layer only
reads the ones loaded before it.

| Layer | What it is | May call the WoW API? |
| --- | --- | --- |
| `Libs/` + `embeds.xml` | Bundled LibStub, CallbackHandler, AceAddon, AceDB, AceConsole, AceEvent, LibDataBroker, LibDBIcon. Never edited. | (third party) |
| `Core/Locale.lua` | `ns.L`: English strings are the keys; a missing key returns the key itself. | No |
| `Data/` | Static tables under `ns.Data`. | No |
| `Logic/` | Pure Lua rules: selection, counts, lockout state, search scoring. | No |
| `Game/API.lua` | `ns.Game`, the wrapper around the game's data APIs. | Yes |
| `Integrations/` | Bridges to other addons and the game's map / achievement systems. | Yes, guarded |
| `Core/Init.lua` | The AceAddon object, saved variables, events, slash commands. | Through `ns.Game` |
| `UI/` | Frames, views, pop-outs, options page. | Yes (frames, input) |

### Data/

| File | Source | Content |
| --- | --- | --- |
| `Mounts.lua` | Generated by `tools/build_data.py` (SimpleArmory + Rarity) | `ns.Data.Expansions`, `ns.Data.Mounts[mountID]` = name, spell, item, icon, exp, tab, section, group, chance, coords, quest, stats, ... |
| `Route.lua` | Generated by `tools/build_data.py` (SimpleArmory planner) | `ns.Data.Route`: the instance / boss tree. The retired route planner used it; the Checklist and the search still read its bosses and instances. |
| `Spots.lua` | Generated by `tools/build_spots.py` (AllTheThings + Mount.db2 source text) | `ns.Data.Spots[mountID]`: the NPCs behind a mount and every spawn point. |
| `Zones.lua` | Generated by `tools/build_zones.py` (UiMap, ContentTuning) | `ns.Data.ZoneVersions`: zones that exist in more than one version. |
| `Lockouts.lua` | Hand-written | How a mount's chance is spent and when it resets (instance / quest / LFG / manual / `camp` specs). |
| `Holidays.lua`, `Events.lua` | Hand-written | Holiday calendar titles and bosses; the IDs behind the event-rare live status. |
| `SpotsExtra.lua` | Hand-written | Spots added to the generated ones. |

Generated files say so in their header and are never edited by hand. The
`tools/verify_data.py` checker compares `Data/` with the game's DB2 tables and
writes `docs/data-verification.md`.

### Logic/

Every file is pure Lua: no WoW globals, no frames. Callers pass in the data,
the clock and predicates such as "is this mount owned", so everything here is
unit-tested under plain Lua 5.1.

| `Checklist.lua` | The daily / weekly / rare-spawn checklist rows and counts. |
| `Alts.lua` | The alt lockout matrix, one Checklist build per character. |
| `Events.lua` | Assault and warfront status lines. |
| `Journal.lua` | List selection, sections, filters, counts. |
| `Zone.lua` | Which mounts belong to a zone. |
| `Attempts.lua`, `Stats.lua`, `Odds.lua` | Attempt counting, kill statistics, drop-chance maths. |
| `Achievements.lua` | Matching mounts to the achievements that reward them. |
| `Lists.lua`, `QuickLists.lua` | Custom lists; the built-in quick lists and the example lists seeded once (Mythic Mounts). |

### Game/API.lua

`ns.Game` is the one wrapper over the game's data APIs (mount journal, saved
instances, quests, LFG, calendar, achievements, statistics, unit info, area
POIs). Every global is looked up at call time and guarded, so an API missing on
this client returns a safe fallback (`false`, `0`, `nil`, `{}`) instead of a
Lua error. `Game.ReportError` sends caught errors to the error handler only
when `/mtrail debug` is on.

### Core/

- `Core/Locale.lua` loads first so every file can use `ns.L`.
- `Core/Init.lua` creates the AceAddon object (`ns.addon`), the AceDB
  database (`ns.db`), the migrations (old AzerothTrail name, retired route,
  old filter layout), attempt counting (`ns.UpdateAttempts`), kill statistics
  (`ns.UpdateStats`), `ns.RecordSeen` for the alt matrix, the game events and
  the slash commands (`addon:OnSlash`).

## The shared namespace

Every file starts with `local ADDON, ns = ...`. `ns` is the private table the
game passes to each file of the addon; it is the only way files talk to each
other. The addon creates no Lua globals of its own apart from the saved
variables `MountTrailDB` (and the legacy `AzerothTrailDB`, emptied once on
load). Named frames (`MountTrailFrame`, `MountTrailMenu`, ...) exist because
`UISpecialFrames` (Esc to close) needs names.

- `ns.Data`, `ns.L`, `ns.Game`, `ns.Map`, `ns.Journal`, `ns.Checklist`, ...:
  one table per module, created in its own file.
- `ns.UI`: everything under `UI/`. Each UI file opens with
  `local UI = ns.UI or {}; ns.UI = UI` and adds functions to it.
- A function another file might not have loaded yet is looked up at call time
  (`if UI.RefreshNav then UI.RefreshNav() end`), not cached in a local.

## Views, window hooks and refresh hooks

**Views.** The main window has one content frame per view key: `journal`
(Home), `checklist` (Lockouts), `here` (Current Zone), `browse`, `holidays`,
`achievements`, `timewalking`, `misc`. A view file registers itself:

```lua
UI.RegisterView("here", { Build = function(parent) ... end, Refresh = function() ... end })
```

`Build` runs once, the first time the view is on screen; `Refresh` runs each
time it is shown and on every `ns.Refresh()` while it is the current view. The
key must be one of the window's known keys (`TABS` in `UI/Frame.lua`).

**Window hooks.** `UI.AddWindowHook(fn)` runs `fn(frame)` once the main window
is built (at once if it already is). The zone panel docks itself this way. A
hook that errors is reported and does not break the window.

**Refresh hooks.** `UI.AddRefreshHook(fn)` runs `fn()` on every
`ns.Refresh()`, even while the main window is closed. Pop-outs, the zone
panel, the alts window and the map tab use it.

## How data flows

```
game event (UPDATE_INSTANCE_INFO, QUEST_TURNED_IN, NEW_MOUNT_ADDED, ...)
  -> Core/Init.lua handler (OnLockoutEvent, OnEnteringWorld, OnCalendarUpdate, ...)
       updates saved state: ns.UpdateAttempts, ns.UpdateStats, ns.RecordSeen
  -> ns.RefreshSoon()   one ns.Refresh on the next frame for a burst of events
  -> ns.Refresh()       (UI/Frame.lua)
       1. refresh hooks: pop-outs, zone panel, alts window, map tab
       2. if the window is shown: the current view's Refresh, then UI.RefreshNav()
       3. drops the shared Checklist build (UI.ForgetChecklistBuild)
```

During one `ns.Refresh` the views, the navigation badges and the pop-outs share
one Checklist build (`UI.ChecklistBuild`), so the checklist is worked out once
per refresh, not once per consumer. Zone changes (`ZONE_CHANGED_NEW_AREA`,
`ZONE_CHANGED`, `ZONE_CHANGED_INDOORS`) do not go through `Core/Init.lua`: the
zone panel, the Current Zone view and the pop-outs each listen on their own
event frame and redraw only when the zone changed. The event-rare status events go to
`UI.EventStatusChanged`, which throttles its own redraw.

## Saved variables

One saved variable, `MountTrailDB`, managed by AceDB. `global` is
account-wide; `char` is per character (AceDB keys it by "Name - Realm").
Defaults are in `addon:OnInitialize` in `Core/Init.lua`; other keys are
created on first use by their owner.

| Key | Owner | Content |
| --- | --- | --- |
| `global.filters` | `Logic/Journal.lua`, `UI/List.lua` | `collected` plus hidden sections per view. |
| `global.collapsed` | `UI/List.lua` and every collapsible list | Collapsed headers, `"<view>|<exp>|<section>"`, `"checklist|..."`, `"alts|..."`, `"nav|..."`. |
| `global.settings` | `UI/Options.lua` | `showUnobtainable`, `rarityColors`, `windowScale`, `navTextSize`, `textHeader` / `textBody` / `textDetail`, `navHideLists`, `navHideQuick`; `checklistShowDone` (Lockouts' Show completed, `UI/ChecklistView.lua`). |
| `global.window` | `UI/Frame.lua` | Current view (`tab`), position, `width` / `height`, `navWidth`, `paneWidth`, `browse` category. |
| `global.navOrder`, `global.navFavorites` | `UI/Nav.lua` | Section order per section; favourite stars. |
| `global.lists`, `global.seededLists` | `Logic/Lists.lua`, `Logic/QuickLists.lua` | Custom lists; which example lists were already seeded. |
| `global.guides`, `global.guideWindow` | `UI/Guides.lua`, `UI/GuideWindow.lua` | The player's guides (`{ [id] = text }`); the guide window's position and mode. |
| `char.guides` | `UI/Guides.lua` | `{ active =, steps = { [guide id] = step }, complete = }`: which guide this character follows and where. |
| `global.popouts`, `global.popoutStyle` | `UI/Popouts.lua` | Open pop-outs (position, size, order, collapsed groups, style, `showDone`); the shared style. |
| `global.zonePanel` | `UI/ZonePanel.lua` | `open`. |
| `global.mapTab` | `UI/MapTab.lua` | Whether the map tab was left selected. |
| `global.altsHidden`, `global.altsWindow` | `UI/AltsWindow.lua` | Hidden characters; window position and size. |
| `global.attemptsByChar`, `global.attempts` | `Core/Init.lua`, `Logic/Attempts.lua` | Attempt counters per character; the old account-wide counter (read only). |
| `global.stats` | `Logic/Stats.lua` | Kill statistics per character. |
| `global.achievementMap` | `Integrations/AchievementScan.lua` | Mount -> achievement IDs, per game build. |
| `global.minimap` | `UI/Frame.lua` (LibDBIcon) | `hide` and the button's position. |
| `global.debug` | `Core/Init.lua` | `/mtrail debug`. |
| `char.last` | `Core/Init.lua` | The last lockout observation (attempt counting, alt matrix). |
| `char.seen` | `Core/Init.lua` (`ns.RecordSeen`), `Logic/Alts.lua` | Name, realm, class, level, faction, reset times. |
| `char.ticks` | `Logic/Resets.lua`, `UI/LockoutHelpers.lua` | Hand ticks with their expiry. |

| `char.campChecked` | `UI/ChecklistView.lua`, `UI/Popouts.lua` | When a no-lockout rare spawn was last checked. |

## Where to find X

| Task | Where |
| --- | --- |
| Add a mount data field | `tools/build_data.py` (`build_mounts`, `_MOUNT_ORDER`), its test `tools/test_build_data.py`, regenerate `Data/Mounts.lua`; read the field in `Logic/` and pass it to the UI. |
| Fix a hand-written lockout | `Data/Lockouts.lua` (shapes in its header), then `python3 tools/verify_data.py`. |
| Add a navigation entry | `UI.NAV` (fixed entries), `UI.NavBrowseEntries` / `Logic/Browse.lua` (Browse), `UI.NavListEntries` (lists), click handling in `UI.NavClick`: all in `UI/Nav.lua`. A new view also needs its key in `TABS` (`UI/Frame.lua`) and a `UI.RegisterView` call. |
| Add an option | Default in `Core/Init.lua` (`settings`), the proxy setting and `Options.Set` in `UI/Options.lua`, the cogwheel item in `UI.SettingsMenuItems` (`UI/Frame.lua`), strings in `Core/Locale.lua`, a case in `tests/options_spec.lua`. |
| Add a pop-out kind | `UI/Popouts.lua`: `UI.PopoutKey`, `UI.PopoutTitle`, `UI.PopoutRows`, `UI.PopoutGroups`, and `refreshWindow` if it follows the player; open it with `UI.OpenPopout({ kind = ... })`. |
| Change a row's click | `UI/List.lua`: `UI.PaneRowAction` / `UI.PaneRowHint` (lists with the detail pane), `UI.RowClickAction` / `UI.HandleRowClick` (zone panel, map tab), the row's `OnClick` in `rowFrame` in `UI/Popouts.lua` (pop-outs). Keep the hint in step with the action. |
| Add a locale string | `Core/Locale.lua`, under the heading of the file that uses it: `L["Text"] = "Text"`. Use it as `L["Text"]`. |
| Change the search | Scoring in `Logic/Search.lua`; what each mount offers to it in `UI.SearchFields` (`UI/Search.lua`). |
| Change the tooltip | `UI.TooltipLines` in `UI/Tooltip.lua` (the detail pane reuses it). |
| Call a new game API | Add a guarded function to `Game/API.lua` and call `ns.Game.X` elsewhere. |
